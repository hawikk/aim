Trust — metadata only

AIM is a security product. It is not a prompt logger. There is no supported path that sends prompt text or tool arguments off the box.

Personal-mode network claim

aim personal binds 127.0.0.1 only and makes zero outbound network calls. No ingest URL, no analytics beacon, no update check. Verify with networking off.

The fleet path (aim join <ingest-url>) is opt-in and talks only to your ingest. It still sends metadata-only events.

What we never collect

  • Prompt text, response text, file contents, code snippets
  • Tool-call arguments, command lines, URLs, env values
  • Emails, names, raw hostnames, IP addresses
  • Keystrokes, screen content, idle time, non-AI-tool activity

Detectors run in memory at the collection point. Matched content is discarded immediately.

Retention (enforced)

Data classDefault window
Usage events90 days
Findings365 days
Audit trail730 days

Ordering audit ≥ findings ≥ events is enforced. A violating config fails closed. Personal mode prunes local SQLite on the same windows. There is currently no legal-hold exemption.

Access control

  • Dashboards show pseudonyms or team aggregates. They cannot resolve a person.
  • Re-identification is a security-role-only, fully audited lookup.
  • The company salt is in the platform KMS / secrets manager, security-role IAM only.
  • CSV export of findings excludes evidence payloads.
  • Personal mode: one implicit local user, loopback only, no accounts.

Honest residual

Metadata-only does not mean nothing personal can be inferred. Tool names, MCP server names, and small-team patterns can still describe activity. Mitigations are access control and aggregate suppression — not prompt capture.

Enforcement is not fleet-wide. See the enforcement capability matrix (markdown). Longer form: trust.md, data minimization.
